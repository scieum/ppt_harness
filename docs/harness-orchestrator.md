# R7 오케스트레이터 규칙

> 2026-10-19 사용자 정정 후 실행 기준: [엄격한 레퍼런스 검증 1.1.0](harness-reference-fidelity.md). 아래의 대표 3장·승인 1회·G08/G09 미구현 설명은 당시 설계 이력이며 현재 실행에는 적용하지 않는다. 현재는 7유형·두 확인 지점과 rules.json 1.1.0을 따른다.

> 구현 현황 (2026-10-19): 로컬 판정기·관리 경로의 쓰기 제한·재개 검사와 48건 회귀 시험을 구현·검증했다. [검증 보고서](../harness/validation-report.md)와 [사용법](../harness/README.md)을 참조한다. 아래 설계 시점의 미구현 표기는 이 현황으로 대체한다. OS 수준 격리와 실제 피그마 업로드·과학 내용 전수 검증은 포함하지 않는다.

## 시작과 재개
AGENTS.md, design.md, harness/rules.json을 읽고 대상 소단원의 입력·진행 상태·승인·입출력 해시를 확인한다.

필수 파일이나 검사 기능이 없으면 통과를 추정하지 않고 누락을 보고한다. 설계 문서만 있는 상태와 실제 실행 가능한 상태를 구분한다.

## 단계 상태

| 상태 | 의미 |
|---|---|
| pending | 실행 대기 |
| running | 실행 중 |
| awaiting_approval | 사용자 계획 승인 대기 |
| passed | 유효한 검사 결과로 통과 |
| failed | 검사 실패 |
| blocked | 입력·도구·판정 부족으로 진행 불가 |

시작 전에 running을 기록하고 유효한 검사 결과가 있어야 passed로 전환한다. 중단된 running은 재개 시 입력·출력·검사 상태를 검증한다.

이 상태는 소단원 파이프라인의 기록이며 다른 도구의 작업 상태와 구분한다.

## 실행 통제
- 실패·미판정 상태에서 후속 단계를 실행하지 않는다.
- 문제 원인에 해당하는 단계로 돌아가 수정하고 의존하는 후속 단계를 재검사한다.
- 통과를 위해 규칙을 완화하거나 승인·판정 기록을 바꾸지 않는다.
- 문서와 검사 규칙이 충돌하면 해당 작업을 멈추고 충돌을 보고한다.
- 같은 오류의 자동 수정은 최대 2회 재시도한다.
- 작업 에이전트의 편집 경계와 판정자의 읽기 전용 경계를 유지한다.

## 완료 판정
오케스트레이터가 다음을 확인한 뒤 완료를 선언한다.
- 최신 입력·규칙·결과에 대한 필수 게이트 통과
- PPTX·DOCX·피그마의 내용과 페이지 대응
- 미해결 수정 0건

피그마 반영 등 필수 작업을 수행하지 못했다면 부분 완료와 미완료 항목을 구분해 보고한다. 실제 수행하지 않은 작업을 완료했다고 말하지 않는다.

천재교육 등 외부 수령처로 결과물을 자동 전송하지 않는다.

## 최종 지침 반영
CLAUDE.md는 생성하지 않는다. R8 종료 후 기존 AGENTS.md에 반영할 보강 초안을 사용자에게 보여주고 승인받는다.

현재 문서는 설계이며 실행 장치나 판정 스크립트를 구현한 상태는 아니다.
