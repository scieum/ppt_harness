> 2026-10-19 사용자 정정 후 실행 기준: [엄격한 레퍼런스 검증 1.1.0](harness-reference-fidelity.md). 아래의 대표 3장·승인 1회·G08/G09 미구현 설명은 당시 설계 이력이며 현재 실행에는 적용하지 않는다. 현재는 7유형·두 확인 지점과 rules.json 1.1.0을 따른다.

> 구현 현황 (2026-10-19): 로컬 판정기·관리 경로의 쓰기 제한·재개 검사와 48건 회귀 시험을 구현·검증했다. [검증 보고서](../harness/validation-report.md)와 [사용법](../harness/README.md)을 참조한다. 아래 설계 시점의 미구현 표기는 이 현황으로 대체한다. OS 수준 격리와 실제 피그마 업로드·과학 내용 전수 검증은 포함하지 않는다.

## 검증 자료
「삼투 현상」 PPT의 복사본과 작은 가상 검사 자료를 사용한다.

원본은 변경하지 않는다. 기존 PPT는 참고·검증 자료로 사용하며 새 제작 파이프라인을 통과한 결과물로 간주하지 않는다.

정상 통과, 실패 유도, 중단 후 재개 시험을 분리한다.

## 필수 시험

| 시험 | 예상 결과 |
|---|---|
| 모든 필수 조건과 유효한 승인 충족 | 해당 게이트 통과 |
| 계획 승인 누락 | 생성·제작 시작 차단 |
| 승인 후 핵심 계획 변경 | 기존 승인 적용 차단·재승인 대기 |
| 보호 대상 시험용 복사본 변경·삭제·이동·이름 변경 | 원본 보호 검사 실패 |
| 출처 누락·범위 미판정·빈 검사 대상 | 통과 차단 |
| 계획과 제작물의 장수 불일치 | 제작물 검사 실패 |
| 발표자 노트 누락 | 제작물 검사 실패 |
| 미해결 검토 오류 존재 | 최종 검수 실패 |
| 피그마 미반영 | 전체 완료 선언 차단 |
| 입력·규칙·출력 변경 후 재개 | 관련 통과 기록 무효화·재검사 |
| 역할 밖 쓰기 시도 | 차단하고 기록 |
| 같은 오류의 자동 수정 2회 실패 | 추가 자동 재시도 중단 |

실패 유도는 격리된 시험 자료에서 수행한다. 승인 증빙 시험에는 모의 기록을 사용하며 실제 사용자 승인으로 취급하지 않는다.

## 전체 슬라이드 리뷰
전체 슬라이드를 렌더링해 시각적으로 검토한다.

- 과학적 주장·수치·수식은 출처와 대조한다.
- 디자인은 design.md를 기준으로 검토한다.
- 교육과정 범위 적합성은 성취기준과 근거를 대조한다.
- 미검토 항목과 미해결 오류는 각각 0건이어야 한다.
- 자동 검사로 확인하지 못하는 사항과 검토의 한계를 기록한다.

## 검증 완료 조건
- 필수 시험의 예상 결과 일치율 100%
- 실행하지 못한 필수 시험 0건
- 미해결 결함 0건

시험 기록에는 실행 ID, 입력·규칙 버전, 예상 결과, 실제 결과와 증빙을 남긴다.

## 현재 상태와 최종 반영
현재는 검증 계획의 설계 단계다. 구현과 시험을 수행하기 전에는 ‘하네스 설계 완료’로만 보고한다.

R8 저장 후 전체 설계 문서의 충돌을 확인하고 AGENTS.md 보강 초안을 제시한다. 사용자 승인 후에만 AGENTS.md를 수정한다. CLAUDE.md는 생성하지 않는다.
