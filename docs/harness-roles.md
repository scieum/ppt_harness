# R6 역할과 편집 경계

> 2026-10-19 사용자 정정 후 실행 기준: [엄격한 레퍼런스 검증 1.1.0](harness-reference-fidelity.md). 아래의 대표 3장·승인 1회·G08/G09 미구현 설명은 당시 설계 이력이며 현재 실행에는 적용하지 않는다. 현재는 7유형·두 확인 지점과 rules.json 1.1.0을 따른다.

> 구현 현황 (2026-10-19): 로컬 판정기·관리 경로의 쓰기 제한·재개 검사와 48건 회귀 시험을 구현·검증했다. [검증 보고서](../harness/validation-report.md)와 [사용법](../harness/README.md)을 참조한다. 아래 설계 시점의 미구현 표기는 이 현황으로 대체한다. OS 수준 격리와 실제 피그마 업로드·과학 내용 전수 검증은 포함하지 않는다.

## 작업 역할

아래 경로는 해당 소단원 폴더를 기준으로 한다.

| 역할 | 담당 | 수정 가능한 폴더 |
|---|---|---|
| 분석 에이전트 | 성취기준·교과서 비교·범위 판정 | research/만 |
| 이미지 에이전트 | 표지·삽화·교과서 크롭 | assets/만 |
| 제작 에이전트 | PPT·대본·발표자 노트 | drafts/만 |
| 판정자 | 규칙 검사·내용 및 시각 검토 | 없음—읽기 전용 |

작업 에이전트는 필요한 다른 역할의 파일을 읽을 수 있지만 수정하지 않는다. 보호 대상 원본은 모든 역할에서 읽기 전용이다.

오케스트레이터는 계획·입력·진행 상태·승인 증빙·이력과 렌더링·피그마·최종본을 관리한다. 작업 에이전트 담당 파일의 수정이 필요하면 해당 역할로 돌려보낸다.

## 판정 결과

판정자는 다음 정보를 반환한다.
- 규칙 ID
- 검사 대상
- 통과 / 실패 / 미판정
- 증빙
- 수정 요청

오케스트레이터가 반환 결과를 checks/report.json에 기록한다. 실패·미판정을 임의로 통과로 바꾸지 않는다.

판정자는 제작물을 수정하거나 사용자 승인·규칙 기준값을 변경하지 않는다.

## 실행 방식

기본은 순차 실행이다. 각 단계는 앞 단계의 게이트 통과 후 시작한다.

역할 분리는 같은 대화 안에서도 적용할 수 있다. 별도 에이전트 사용 여부는 실행 환경에 맞추되 편집 경계를 유지한다. 역할을 나누었다는 사실만으로 독립 검증이 보장된다고 표현하지 않는다.

## 자연어 트리거

| 문구 | 동작 |
|---|---|
| “○○ 소단원 시작” | 근거 분석과 계획 작성까지 진행한 뒤 승인 대기 |
| “이 계획 승인, 제작 진행” | 현재 계획을 특정해 승인 기록 후 이미지 준비부터 진행 |
| “○○ 이어서 진행” | 해시·승인·게이트 상태를 확인하고 유효한 지점부터 재개 |
| “○○ 검수만” | 제작물 수정 없이 검사 결과만 보고 |
| “○○ 수정: …” | 변경 영향을 판정하고 해당 단계로 복귀 |

승인 대상 계획이 불명확하면 추정해 진행하지 않는다.

“검수만”에서는 제작물은 변경하지 않으며, 검사에 필요한 렌더링과 검사 기록만 생성·갱신한다.

## 구현 상태

이 문서는 역할과 권한 경계의 설계다. 폴더별 쓰기 제한을 강제하는 실행 장치나 에이전트는 아직 구현하지 않았다.
