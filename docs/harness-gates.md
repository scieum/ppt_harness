# R5 게이트와 판정

> 2026-10-19 사용자 정정 후 실행 기준: [엄격한 레퍼런스 검증 1.1.0](harness-reference-fidelity.md). 아래의 대표 3장·승인 1회·G08/G09 미구현 설명은 당시 설계 이력이며 현재 실행에는 적용하지 않는다. 현재는 7유형·두 확인 지점과 rules.json 1.1.0을 따른다.

> 구현 현황 (2026-10-19): 로컬 판정기·관리 경로의 쓰기 제한·재개 검사와 48건 회귀 시험을 구현·검증했다. [검증 보고서](../harness/validation-report.md)와 [사용법](../harness/README.md)을 참조한다. 아래 설계 시점의 미구현 표기는 이 현황으로 대체한다. OS 수준 격리와 실제 피그마 업로드·과학 내용 전수 검증은 포함하지 않는다.

## 필수 게이트

| ID | 게이트 | 통과 조건 | 실패 시 복귀 |
|---|---|---|---|
| G01 | 근거 분석 | 내용 항목의 출처·범위 판정 기록률 100%, 미판정 0건 | ① 근거 분석 |
| G02 | 페이지 계획 | 필수 항목 누락 0건, 페이지 번호 중복·누락 0건, 목표 장수 일치 | ② 페이지 계획 |
| G03 | 제작 시작 승인 | 현재 계획에 연결된 사용자 승인 기록 1건 이상 | ② 페이지 계획 |
| G04 | 이미지 준비 | 사용 자산의 파일·출처·용도 기록률 100%, 검토 미완료 0건 | ③ 이미지 준비 |
| G05 | 제작물 | PPT 장수·대본 항목 수가 계획과 일치, 노트·출처 누락 0장 | ④ PPT·대본 제작 |
| G06 | 최종 검수 | 슬라이드별 렌더링·시각 검토 기록률 100%, 미해결 오류 0건, 피그마 프레임 대응률 100% | 문제 원인에 따라 ①~④ |
| G07 | 원본 보호 | 보호 대상의 변경・삭제・이동・이름 변경 각각 0건 | 변경 감지 지점에서 중단·원인 확인 |

각 기록률의 분모는 해당 단계에서 검사할 전체 항목 수다. 검사 대상이 비어 있거나 검사를 실행하지 못한 경우 자동 통과시키지 않는다.

## R1-A 금지 조건 연결

- INV-01 → G03: 승인 없이 이미지 생성·PPT 본 제작을 시작하면 실패한다. G03은 두 작업의 실행 전에 적용한다.
- INV-02 → G07: 보호 원본의 변경을 감지하면 진행을 중단한다. 동기화 등 외부 변경과 작업에 의한 변경을 구분하며, 원본을 임의로 복원하거나 기준 해시를 갱신해 통과시키지 않는다.

## 사람 승인 지점

작업을 멈추고 사용자 승인을 받는 지점은 ② 페이지 계획 확정 직후 한 곳이다.

승인은 현재 계획과 연결된 사용자 응답을 증빙으로 기록한다. 에이전트가 사용자를 대신해 승인하거나 응답 부재를 승인으로 처리할 수 없다.

피그마 검토는 수정 의견을 주고받는 단계로 운영한다. 별도의 최종 승인 응답은 요구하지 않지만, 요청된 수정이 남아 있으면 완료하지 않는다.

## 보충·심화와 교육과정 적합성

보충·심화 항목마다 다음을 기록하고 계획 승인에 포함한다.
- 출처
- 포함 이유
- 기본 수업과의 구분

적합성을 판단하지 못한 내용은 미판정으로 남겨 G01 통과를 막는다. 기록의 존재만으로 교육과정 적합성을 입증했다고 간주하지 않는다.

## 기계 검사와 내용 검토의 구분

과학적 정확성, 그림 잘림, 요소 겹침 등의 검토에는 결과와 증빙을 남긴다. 스크립트는 기록의 누락, 검토 상태와 미해결 오류 건수를 검사한다.

검토 기록이 존재한다는 사실과 내용 자체가 정확하다는 판단을 구분한다. 스크립트 통과를 과학적·시각적 품질의 완전한 보증으로 표현하지 않는다.

## 실패 처리

실패와 미판정은 모두 다음 단계 진행을 막는다. R3의 문제 유형별 복귀 단계에 따라 수정하고, 변경된 단계와 의존하는 후속 단계를 재검사한다.

같은 오류의 자동 수정은 최대 2회 재시도한다. 계속 실패하면 현재 상태를 보존하고 원인과 필요한 결정을 보고한다.

## 계획 변경과 재승인

다음 변경은 ②로 돌아가 같은 승인 지점에서 재승인받는다.
- 소단원 범위
- 학습 목표
- 슬라이드 수
- 페이지별 핵심 메시지
- 보충 내용

의미가 같은 문구 수정, 배치 조정, 승인된 용도의 이미지 교체는 재승인 없이 관련 검사를 다시 수행한다.

## 구현 상태

위 ID와 조건은 설계안이다. 실제 검사 규칙은 후속 구현 시 harness/rules.json에 두고, 이 문서는 규칙 ID를 참조하도록 정리한다. 판정 스크립트는 아직 구현하지 않았다.
